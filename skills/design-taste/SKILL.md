# Purpose

Competent-looking and designed are different. The difference is whether each decision was made or defaulted, and defaults are what make an interface look generated.

# When to use

Any surface where how it looks matters: dashboards, landing pages, marketing, anything being redesigned.

# When not to use

Internal tooling nobody sees, or a one-line copy change. Taste applied to a rename is procrastination.

# Inputs

The product, its users, the existing tokens, and what the surface is actually for.

# Process

Establish hierarchy first — what must be seen in order. Choose type for that hierarchy, not from a favourites list. Spend the accent in one place. Then remove what is not carrying weight.

# Decision rules

Hierarchy comes from family, weight, size, tracking, leading, measure, alignment and density — never from size alone. One tracking value at every size is a tell. Prefer optical over mathematical alignment.

# Constraints

Every value lands on a token; no raw hex in a component. Contrast is measured, never estimated.

# Quality checks

Remove the brand and the copy. Does the composition still say what matters first? If not, the hierarchy is decoration.

# Common failures

Uniform emphasis, so nothing leads. Accent used everywhere, so it means nothing. Type chosen by reputation rather than by role.

# Output format

The decisions and their reasons, plus the measured contrast table.

# Examples

A dense billing table gets tabular figures, a tighter density and one accent on the overdue state — not a hero, not a gradient.
